# 操作说明

## 工具与验证

`fs.read/write/edit/delete` 和 `bash` 面向已绑定工作区。Shell 的 `workspaceMode` 与 `executionScope` 描述真实写入及执行范围；Host/外部权限和工作区 Plan 是分别检查的。已确认 Plan 内的 Bash 命令可以作为执行示例，不要求为无关的空格、日志路径或同范围命令变化重新确认；新目标、删除操作和扩大写入范围仍由权限层判断。

项目 README、构建脚本和用户指令决定验证环境。用户要求容器时，在对应容器里执行项目构建脚本，不因为宿主机存在编译器就改成宿主构建。交互 Shell 的输入必须跟随该调用的实际工具参数，不把一次工具调用误认为永久切换了后续调用环境。

工具结果包含成功、失败或拒绝的原始事实。遇到拒绝先读原因和当前 Plan 范围；修正必要的输入或范围，不逐字重试相同错误。`plan.progress` 引用当前 run 的 ToolRecord ID 和当前 Todo ID；失败记录不能证明步骤完成。验证报告应区分已执行、已通过、未执行或环境不支持。

## 模型与上下文

模型选择框显示用户命名，二级选项选择该模型支持的推理强度。推理阶段显示状态与耗时，不展示原文。较长耗时本身不能证明 Agent Loop 卡住，需结合 Provider 完成事件、工具耗时和最后错误判断。

上一次调用的缓存命中率和整个 session 的缓存命中率使用相同公式：输入命中缓存 token / 输入 token。上下文球关注最后已结算调用，右上角关注整个 session，设置页给出对话 token 明细。无法从比例差异单独判断计算错误。

工具目录和系统指令在一次运行中保持稳定；工具结果、产品 Skill 正文和新消息追加到历史。不要为提高命中率删改历史事实，或通过降低推理强度、隐藏错误和伪造用量制造改善。
